## Architecture rules
- Game rules live in pure modules `src/game/engine.ts` and `src/game/symmetry.ts` (no React); UI only calls them. Why: logic stays unit-testable.
- Mirror edits and contextual hints use the pure engine action helpers; gameplay undo stores previous board snapshots in memory. Why: invalid drops cannot consume moves and undo restores exact orientations without altering saved progress.
- Every level in `src/game/levels.ts` carries a `solution`; tests assert it solves. Why: guarantees no unsolvable puzzle ships.
- All UI text comes from `src/i18n/{en,hi,mr}.ts` via `useSettings().t`. Why: trilingual support with no hardcoded strings.
- Client-only persistence through `src/lib/settings.tsx` (localStorage in try/catch, read in useEffect). Why: no backend, hydration-safe.
- Space mode physics live in pure `src/game/optics.ts` (free-angle ray tracing, gravity/wind stepping); levels in `src/game/spaceLevels.ts` each carry a tested `solution`. Why: same testable-engine rule as Mirror Maze.
- Space level layouts 11+ were generated by tracing a designed tool solution and placing planets on the beam ends; tests assert each is solvable, on-board, and not solved by the sun alone. Why: keeps hard multi-planet worlds fair.
